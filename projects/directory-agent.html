Case study · AgentSwitch Seat 27

Directory Agent

Contacts spine over Party / PartyRelationship. One MCP agent for customer deduplication and relationship lookup goals.

Repository All School of AI projects

Problem

CRM-style contact books accumulate duplicates and weak relationship context. Operators need agent-assisted dedupe and “who do we know at this company” answers with human approval for writes.

Role and contribution

Built the seat-27 directory agent against the AgentSwitch harness: goals for deduplicate_customers and who_do_we_know, plus gap report vs Attio and a set of filed platform bugs documented in the repo.

Architecture

Operator prompt
  → Directory MCP agent
  → Party / PartyRelationship spine
  → Goals: directory.deduplicate_customers, directory.who_do_we_know
  → Human approval for record-changing actions

Technical decisions

  • MCP as the integration surface for both “books”.
  • Evidence-first docs: gap report, bugs list, completeness audit.
  • Harness-oriented layout for reproducible seat evaluation.

Outcome / evidence

Public A27-directory-agent repository with harness config, docs, and filed bug notes. Continues into AgentSwitch Advanced seats work.
