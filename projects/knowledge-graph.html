Case study · School of AI Assignment 5

System Design Knowledge Graph

An evolving knowledge graph for system-design learning: ingest engineering blogs, extract concepts and relationships with structured LLM agents, and recommend what to study next.

Repository All School of AI projects

Problem

System-design material is scattered across blogs. Learners need a durable graph of concepts and relationships, not one-off summaries, plus recommendations grounded in what is already in the graph.

Role and contribution

Designed and implemented the FastAPI service, MCP tool surface, Gemini JSON planner loop, SSE live agent log, NetworkX persistence, and frontend ingest UI described in the project README.

Architecture

Client UI
  → POST /ingest/stream (SSE)
  → FastAPI orchestrator / agent loop
  → Gemini JSON planner selects MCP tools
  → MCP tools: extract article → concepts → relationships → merge → recommendations
  → GraphManager persists NetworkX graph to data/graph.json

Technical decisions

  • Pydantic-validated structured outputs for concepts, relationships, and recommendations.
  • SSE so the UI can show tool steps live instead of a single blocking response.
  • Persistent graph merge rather than ephemeral chat memory.

Outcome / evidence

Public repository with documented setup, architecture diagram, and runnable stack. Featured as the highest complexity/info entry in the School of AI catalog.
